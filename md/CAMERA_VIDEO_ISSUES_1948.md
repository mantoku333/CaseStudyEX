# 録画 2026-11-15 19:48（246秒）と CameraTrace.log の突き合わせ

方法: `Logs/CameraTrace.log`（部屋・Fog・映っているカメラが変わったフレームの記録）を読み、
動画は15fpsで3,690フレームを抽出して黒率と画面変化量を全フレーム測定。動画の時刻 = ログの時刻 − 82.75秒。

## 1. ポータルの遷移用カメラが動いていた（原因確定・修正済み）

止めたはずの遷移用カメラ（`CN_PortalTransitionRuntime` / `CN_VerticalPortalTransitionRuntime`）が、
ポータルに触れた瞬間に優先度30で起動していた。動かす処理は止めてあったので、
**ポータルの中にいる間、画面が古い位置で固まる**。部屋とFogは先に切り替わるので、その間は黒くなる。

`useTransitionCamera = false` のチェックを毎フレームの処理にしか入れておらず、
ポータルに入った瞬間の呼び出し（`HandlePlayerEntered`）に入れ忘れていた。

ログで「部屋は切り替わったのに古い絵のまま」だった区間は、すべてこれ。

| 動画の時刻 | 場所 | 長さ |
|---|---|---|
| 13.4s、38.2s、39.5s、41.4s、194.3s、196.7s、199.1s、205.9s、225.9s、233.5s | 各ドア | 1フレーム（カット時の黒フレーム） |
| 167.4〜167.7s | ステージ2の登り（Col_202 → Col_203） | 0.4秒 |
| 169.5〜172.4s | 同上、落ちて戻ったとき | **3.0秒** |
| 176.5〜181.9s | 同上、2段目の足場の前後 | 5.4秒のうち黒が3.4秒 |

同じ原因で起きていたこと:
- ドアの手前0.5秒ほど、追従カメラが止まる（例: 95.6〜96.2s、プレイヤーが3.8u歩く間カメラは静止）
- 追従カメラに切り替わった2〜3フレーム後に画面が飛ぶ（167.8s と 181.9s で縦に3.5u / 1.9u、75.3s で横に1.7u）。
  遷移用カメラの古い位置を追従カメラに書き込む処理も一緒に走っていた

17:52 の「Col_202 の右上隅で最長1.4秒黒くなる（原因未特定）」と、18:27 の「カット時の黒フレーム」も同じ場所・同じ現象。

修正: `StartTransitionCamera` と `AlignDefaultFollowCameraBeforeCommit` の先頭で `useTransitionCamera` を確認する
（`RoomCameraPortal` / `VerticalRoomCameraPortal`）。ポータル自体は置いたまま。

## 2. ボス戦のあいだ部屋が真っ黒（原因確定・修正済み）

103.4〜124.9s。前回の修正は「ボス用コンポーネントと同じオブジェクトにある部屋」を有効にするものだったが、
最初のボスは `BossArea` プレハブを部屋（Col_109）の中に置く形で、プレハブには部屋のコンポーネントが無い。
そのため何も起きず、有効な部屋は手前の廊下（Col_107）のままだった。

元の実装で消えていた理由: ポータルに触れた時点（ボスエリアの4u手前）で、ポータルが行き先の部屋を有効にしていた。
今回の作り直しで「部屋を決めるのは位置の判定だけ」にしたため、部屋が切り替わるのは境界から0.25u入った時点になり、
ボス戦の開始（体がボスエリアに触れた時点で部屋の判定を止める）に先を越されるようになった。作り直しが原因の退行。

修正: 同じオブジェクトに無ければ、ボスエリアの中心がある部屋を使う（`RoomCameraTrigger.ResolveEncounterRoom`）。

## 3. ステージ1→2のワープ扉の前で0.7秒黒くなる（未修正・配置の問題）

128.9〜129.5s。扉（267.2, -53.8）は Col_109 の右端（264.4）の外、Col_111 の中に立っている。
扉に近づくと有効な部屋が Col_111 になり、Col_109 がFogで隠れる。Col_111 のその位置には何も無いので、扉以外が黒い。
コードは配置どおりに動いている。Col_109 の当たり判定を扉まで広げれば消える。
