# 録画 2026-11-15 18:27（228秒）

15fpsで3,414フレームを抽出し、黒率90%以上の区間を全件、絵で確認した。時刻は動画内の秒。

## 1. ボス戦の間ずっとボス部屋が真っ黒（86〜106秒）

**原因（確定）**: ボス戦のカメラは、プレイヤーの体がボス部屋のコライダーに触れた瞬間に確保され、
その間は部屋の判定が止まる（`EncounterCameraOwnership.IsActive`）。一方、部屋が切り替わるのは
0.25u入ってから。必ずカメラ確保が先に来るので、アクティブな部屋は手前の廊下のまま固定され、
Fogはボス部屋を覆い続けた。以前はポータルが先に部屋を切り替えていたが、その権限を外したのは私の変更。

**修正**: ボス戦がカメラを持っている間は、そのボス部屋をアクティブな部屋として公開する
（`RoomCameraTrigger.PublishEncounterRoom`）。カメラの優先度には触らない。
ボス戦が部屋カメラを戻さずに終わった場合（死亡・ロード）に備え、終了後に一度だけ部屋カメラを再適用する。

## 2. 追従エリアへ切り替わる瞬間に真っ黒（20.9 / 139.1〜139.3 / 148.9 / 157.7 / 169.1 / 181.3 / 208.3 / 212.3秒）

黒いフレームは全て「前のカメラの絵 ＋ 新しい部屋のFog」だった。

**原因（有力・実機未確認）**: プレイヤーの Rigidbody2D は補間なしなので、Cinemachine の Smart Update では
追従カメラは物理ステップ（50Hz）でしか計算されない。部屋の切り替えは LateUpdate で起きるため、
そのフレームの追従カメラは「前の部屋の枠で計算した位置」のまま映る。固定エリアから来た場合、
それは固定カメラと同じ絵になる。Fogは同じフレームで切り替わるので黒くなる。
ヒットストップ（timeScale 0）の間は物理ステップが来ないので、その間ずっと黒い。
139.1〜139.3秒は攻撃エフェクトが3フレーム静止しており、これに一致する。
17:52の録画の「Col_202 の隅で最長1.4秒黒い」も同じ仕組みの可能性が高い。
前回入れた `Prioritize()` はカメラの選択を早めただけで、選ばれた追従カメラの位置は古いままだった。

**修正**: 部屋を切り替えた直後に、追従カメラの位置を同じフレームで計算し直す
（`CameraManager.RefreshFollowCameraStateNow`）。

## 3. ステージ3へのワープ直後に2回黒くなる（110.0〜110.1 / 110.9〜111.3秒）— 原因未特定

Col_222 の扉 → Col_301。カメラは扉の位置にいるのに、Fogが Col_301 を開けていない。
この直後（111.4〜112.5秒）に会話イベントが始まる。録画からは、どの部屋がアクティブかを判別できなかった。
2 の修正で消える根拠はない。

## 追加したもの: カメラの記録ログ
